# rls-multitenancy-demo

[English](README.md) | 日本語

> コードのコメントを日本語にしたもの（画面も日本語）は [`ja/`](ja/) にあります。本体（`sql/` `app/` など）は英語です。ファイルのパスは英語版のものを指しています。

取引先（会社）ごとに「見えるデータ」を分ける、Row Level Security（RLS）の小さな学習用デモです。1つのプロジェクトに2社の請求書を入れて、RLSの前後で何が見えるかを確かめます。

> **個人の学習記録として作ったサンプルです。** 特定の会社の公式サンプルではなく、本番の設計の見本でもありません。
> English summary: SQL to try Postgres Row Level Security on a Supabase project with a simple multi-tenant invoice model (tenants / memberships / invoices), including checks as `anon`, as one tenant's user (JWT claims impersonation in the SQL Editor), and a cross-tenant write attempt.

## 請求書ポータル（`app/`）

ログインすると、自分の取引先の請求書だけが出てくる、小さな画面です（HTML 1枚、ビルド不要。`supabase-js` はCDNから読み込みます）。画面のコードには、取引先で絞る条件を書いていません。見える行は、上のRLSのポリシーが決めます。

```bash
# 前提: 上の sql/01〜05 を実行済み。Authentication → Users で、デモ用ユーザーを2人作る
#       （例: demo-acme@example.com / demo-globex@example.com、Auto Confirm にチェック。パスワードは自分で決める）
# sql/app/01_portal_users.sql を実行して、ユーザーを取引先に結びつける
cd app
cp config.example.js config.js     # URL と publishable キーを入れる（config.js は .gitignore 済み）
python3 -m http.server 8765 --bind 127.0.0.1   # → http://127.0.0.1:8765/index.html
```

- 画面の「開発者向けテスト」で、①絞り込みなしで全件を読む（自社の分だけが返る）、②他社のIDで追加する（`42501` で拒否される）を試せます。
- 動作確認（2026年10月）: 2人のユーザーで実際にログインして、一覧・合計・追加・上の2つのテストを確かめました。前の「SQL Editorでのなりきり」と同じ結果でした。
- 費用: ユーザー認証とデータの読み書きのみ。Freeプランは月間アクティブユーザー5万人まで（ドキュメントより）。
- 注意: 所属が複数の人、管理者、パスワードの再設定、更新・削除のポリシーは扱っていません。デモ用ユーザーのパスワードは、リポジトリに入れないでください。

## 必要なもの

- Supabaseのプロジェクト（私はFreeプランのデモで確認しました）
- ブラウザだけ（SQL Editorを使います）
- ダミーのユーザー2人: **Authentication → Users → Add user** で、`alice@example.com` と `bob@example.com` を作ります（**Auto Confirm User** にチェック）。パスワードは自分で決めてください。このリポジトリには書いていません

## 使い方

1. 上のダミーユーザーを作ります。
2. SQL Editorで、`sql/01` から順に実行します。
   - `01` を実行すると、「RLSなしでテーブルを作ろうとしています」という確認が出ます。**ここは「Run without RLS」を選びます**（`03` で「RLSがないと何が起きるか」を見るためです。デモ用プロジェクトでだけ行ってください）。
   - `03` / `06` / `07` / `08` は `begin;` から始まります。実行したあとに `rollback;` を実行して、トランザクションを閉じてください。
3. 期待される結果は、各ファイルの先頭のコメントに書いてあります。
   - `03`: 全社の4件が見える（RLSの前）
   - `06`: 0件
   - `07`: Acmeの2件だけ（`bob@example.com` に変えると、Globexの2件だけ）
   - `08`: `ERROR: 42501: new row violates row-level security policy for table "invoices"`

私は、この順番でゼロから通して実行して、上のとおりの結果になることを確認しました（2026年10月）。

## 私が勘違いしたところ

`08` のファイルのコメントにも書きましたが、`insert ... select` で他社の行を追加しようとすると、Aliceには他社の行が**そもそも見えない**ので、selectが0行になり、**エラーにならず「0行を追加して成功」**します。ポリシーを確かめるときは、他社のidを明示して追加しないと、効いているのかどうかが分かりません。

## 注意

- **これは学習用の最小構成です。** 本番では、書き込み・更新・削除のポリシー、ロール（管理者など）、パフォーマンス（ポリシーで使う列の索引）なども考える必要があります。私は試していません。
